
             ---===[ Qubes Security Bulletin 116 ]===---

                              2026-07-29

       Multiple Xen issues (XSA-500, XSA-505, XSA-506, XSA-507)

User action
------------

Continue to update normally [1] in order to receive the security updates
described in the "Patching" section below. No other user action is
required in response to this QSB.

Summary
--------

The Xen Project published the following security advisories on
2026-07-29:

XSA-500 [3] "grant-table: type confusion in grant-copy":

| When grant-copy operations are processed, the respective grant may or may
| not already be in use by another operation (a mapping or another copy).
| For all copy operations the referenced guest frame is looked up.  When
| another operation is already active for the grant (the grant is "pinned"),
| what is being supplied back to actually carry out permission checks and
| copy operation may not be consistent: The permission check may be carried
| out on a page different from the one involved in the copy.


XSA-505 [4] "evtchn: Race between FIFO expand and reset":

| The EVTCHNOP_expand_array hypercall checks for whether FIFO event
| channels are enabled, but without holding the correct lock.  It can race
| with EVTCHNOP_reset, resulting in deferencing a NULL pointer.


XSA-506 [5] "correct buffer checks for DM_OP hypercalls":

| Parts of the DM_OP handling code assumes the caller has provided the
| required number of buffers for the given operation without any checking
| being done.  As a result, certain operations might access stack
| rubble as structures are possibly uninitialized.

XSA-507 [6] "PoD: Don't try to reclaim special pages":

| A guest started with Populated on Demand enabled (PoD) can attempt to
| reclaim pages which aren't regular guest RAM.  This can cause corruption
| of memory management state in Xen.

Impact
-------

The impact vary between across the published advisories.

1. XSA-500 and XSA-507: A malicious qube may be able to compromise the
whole host.

2. XSA-505: A malicious qube with virt_mode set to "pv" may be able to
compromise the whole host. The same impact applies to a stubdomain for
a HVM qube - but in this case attacker needs for combine it with
another vulnerability (in QEMU) to gain access to the stubdomain.

3. XSA-506: A stubdomain for a HVM qube may be able to leak
data from other qubes in the system. Similar to XSA-505, to exploit
this issue, the attacker first needs to gain access to the stubdomain
via another vulnerability (in QEMU).

Affected systems
-----------------

1. XSA-500: All systems are affected.

2. XSA-505: Systems with any qube set to "pv" virt mode are more
exposed, but other systems are affected too (via stubdomains for at
least sys-net and sys-usb), just exploiting the vulnerability is
harder there.

3. XSA-506: All systems having untrusted HVM are affected - this
applies to the default configuration of Qubes OS - sys-net and sys-usb
are HVM.


4. XSA-507: Only systems with a qube included in memory balancing but
set to use the kernel from within a qube, that either does not support
memory hotplug, or its virt_mode is set to HVM. The default
configuration is not affected, neither a commonly used HVMs (like
Windows). Support for memory hotplug can be checked by looking for
`CONFIG_XEN_BALLOON_MEMORY_HOTPLUG` option in the Linux kernel build config.


Patching
---------

The following packages contain security updates that address the
vulnerabilities described in this bulletin:

  For Qubes 4.3, in dom0:
  - Xen packages, version 4.19.5-2

These packages will migrate from the security-testing repository to the
current (stable) repository over the next two weeks after being tested
by the community. [2] Once available, the packages should be installed
via the Qubes Update tool or its command-line equivalents. [1]

Dom0 must be restarted afterward in order for the updates to take
effect.

If you use Anti Evil Maid, you will need to reseal your secret
passphrase to new PCR values, as PCR18+19 will change due to the new Xen
binaries.
